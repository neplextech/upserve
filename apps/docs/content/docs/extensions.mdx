title: Extend Upserve
description: Choose the extension point for a new release source, update protocol or metadata store.
---

You can add a release source, update protocol or cache store without changing Upserve. Official integrations use the same public contracts available to your code.

| You want to change                          | Implement    | Start here                                       |
| ------------------------------------------- | ------------ | ------------------------------------------------ |
| Where release metadata and assets come from | `Provider`   | [Custom providers](/docs/custom-providers)       |
| What routes and responses your updater uses | `Adapter`    | [Custom adapters](/docs/custom-adapters)         |
| Where cached metadata is saved              | `CacheStore` | [Custom cache stores](/docs/custom-cache-stores) |

Start with the smallest contract that fits your task. For example, a new JSON response format usually needs an adapter, not a new provider. Your adapter can reuse GitHub and the existing cache.

The `defineProvider()`, `defineAdapter()` and `defineCache()` helpers check the contract while preserving your object's inferred properties. They don't wrap or sandbox your code. Plugins run with the application's permissions, so only install integrations you trust.

Each guide below includes a complete implementation and a deterministic test. The [API reference](/docs/api#extension-contracts) documents the full method signatures and shared services.
