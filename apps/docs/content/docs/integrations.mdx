## Tauri v2

Use `tauri()` from `@neplex/upserve-tauri`. Publish Tauri's `latest.json` and its referenced binaries in the same release. Set the updater endpoint to `/APP/stable/tauri/{{target}}/{{arch}}/{{current_version}}`. `/APP/stable/tauri/latest.json` provides static manifest compatibility. `manifest` overrides the source filename. Signatures are retained byte for byte. Invalid versions, missing signatures or missing referenced binaries fail closed; no applicable platform/update returns 204. Custom Tauri targets can use the static endpoint.

## electron-builder / electron-updater

Use `electron()` from `@neplex/upserve-electron` with generic feed URL `/APP/stable/electron/`. Stable maps to `latest`; use `channels: { prerelease: 'beta' }` in adapter options for beta feeds. Supported manifests include `latest.yml`, `latest-mac.yml`, `latest-linux.yml` and Linux architecture suffixes. Publish the original YAML, NSIS installer or macOS ZIP/DMG or Linux artifacts, and blockmaps. The YAML must have version, files, SHA-512 base64 checksums and sizes matching release assets. Paths must be relative basenames in the same release. YAML is returned unchanged.

Web installers (`packages`), absolute external file URLs and signed feed envelopes are rejected. Electron's native Squirrel autoUpdater is a different protocol and is unsupported. Differential generation is outside scope. Existing `.blockmap` assets and Range requests are passed upstream. Configure electron-updater's generic provider `useMultipleRangeRequest: false` for GitHub delivery, which supports single ranges; do not assume multipart range support. Keep old release artifacts available for old blockmap lookups. Downloads are verified by the client using the original checksums.

## Direct Android APKs

Use `android()` from `@neplex/upserve-android`. Publish `latest-android.json` (override `manifest` if needed). Endpoints are `/APP/stable/android/latest.json` and `/APP/stable/android/update/CURRENT`.

```json
{
  "version": "1.2.0",
  "versionCode": 12,
  "notes": "Release notes",
  "pub_date": "2026-01-01T00:00:00Z",
  "android": {
    "url": "https://github.com/owner/repo/releases/download/v1.2.0/app.apk",
    "sha256": "aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa",
    "size": 12345
  }
}
```

The checksum shown is illustrative; generate the actual digest in release CI. `versionCode`, `minimumVersion` and `compatibility` are optional. A `transform(input)` hook maps existing formats. `compatible(manifest, request)` can enforce ABI, SDK or minimum-version policies; default behavior compares semantic versions only. Clients must verify size, SHA-256, package name and signing certificate before prompting installation. Upserve never requests signing keys.

OPPA's current generator and Rust consumer were inspected locally: their manifest uses version, notes, pub_date and android URL/SHA-256/size and works with this default format. No OPPA behavior is embedded in the server.

Protocol references: [Tauri updater](https://v2.tauri.app/plugin/updater/), [electron-updater generic provider source](https://github.com/electron-userland/electron-builder/blob/master/packages/electron-updater/src/providers/GenericProvider.ts).
