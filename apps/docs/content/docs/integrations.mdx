---
title: Choose an integration
description: Find the guide for your existing updater without changing its release protocol.
---

Choose the guide that matches the updater already installed in your application. Each guide walks through the packages, release assets, server setup and client configuration.

| Your application                            | Guide                                | What you publish                                 |
| ------------------------------------------- | ------------------------------------ | ------------------------------------------------ |
| Tauri v2 desktop app                        | [Tauri](/docs/tauri)                 | `latest.json`, signed updater artifacts          |
| electron-builder app using electron-updater | [Electron](/docs/electron)           | Platform YAML, installers and existing blockmaps |
| Android app distributed outside Google Play | [Android](/docs/android)             | `latest-android.json` and an APK                 |
| CLI, desktop app or another custom client   | [Custom applications](/docs/generic) | Release assets; no adapter manifest required     |

Electron's native `autoUpdater` uses other protocols and isn't supported by the Electron adapter. Android doesn't have a universal sideloaded update protocol, so you'll implement the client check and installation flow yourself.

Need a different protocol? You can [write an adapter](/docs/custom-adapters) without changing Upserve. You don't need to understand the extension contracts to use a built-in integration.
